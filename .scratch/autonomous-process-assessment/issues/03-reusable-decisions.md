# Demonstrate reusable design knowledge across two related cases

Type: prototype
Status: open
Blocked by: none

## Problem

The project has documentation and read receipts, yet generalized user intent can narrow into a local fix or a known mismatch can be accepted as a limitation.

## Outcome

Use one real pattern, such as coherent asset footprint across visual frame/hit target/menu anchor, or shared UI input/scroll behavior. First inspect the existing published workflow, UI, architecture and asset documents. Identify whether the actual gap is capture, retrieval, application, conflicting guidance, or acceptance judgment.

Produce a reviewable proposal in scratch: one authoritative rule with scope, rationale, positive/rejected examples, exceptions, owner and normal discovery path. Use an independently prepared second case to check that another agent can find the rule and explain its application without being handed the answer. Keep the exercise offline or use existing retrospective cases; do not inject a synthetic task into the live project.

## Acceptance

- No duplicate knowledge system; proposal uses existing authoritative docs and identifies stale competing material.
- Relevant specification/review changes make in-scope mismatches visible as unfinished work unless an actual deferral is agreed.
- Demonstrate both an applicable case and a legitimate exception; avoid speculative global abstraction.
- Record evidence of retrieval and judgment, not merely a mandatory read acknowledgment.
- If adoption requires code/documentation/process changes, publish scoped delivery tickets and identify the necessary product decision before applying them.
